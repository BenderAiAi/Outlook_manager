# Outlook Exporter

Программа выгружает вложения и письма из основного ящика текущего профиля классического Outlook для Windows. Запускайте её в обычном сеансе Windows, где Outlook уже настроен. [Сравнение версий Outlook](https://support.microsoft.com/en-us/outlook/getstarted/feature-comparison-between-new-outlook-and-classic-outlook#bkmk_extensibility)

## Подготовка компьютера

Скопируйте папку проекта на рабочий компьютер. Используйте CPython 3.10 или 3.11 и рабочее окружение с уже установленным `pywin32==305`. Для Python 3.10 также нужен `tomli==2.0.1`. Версии взяты из списка `requirements-workstation — копия.txt` проекта `Bond_recons`. [Сборки pywin32 305](https://pypi.org/project/pywin32/305/#files)

При необходимости создайте отдельное окружение в PowerShell. Если зависимости уже есть в рабочем Python, пропустите этот шаг.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

В командах ниже `python` обозначает Python из рабочего окружения. Если создали `.venv`, используйте `.\.venv\Scripts\python.exe`.

## Мастер настройки

Откройте классический Outlook. В PowerShell из папки проекта запустите мастер.

```powershell
python outlook_setup.py --config config.toml
```

Мастер открывается по адресу `http://127.0.0.1:8765` и сохраняет настройки в `config.toml`. Раскройте карточку правила, чтобы сверить фильтр, папки Outlook и сохранение на диск. На узком экране эти блоки расположены друг под другом.

1. **Отбор писем.** Выберите точную тему или введите фрагмент темы. Сравнение темы и адреса отправителя не учитывает регистр. Можно добавить полный адрес отправителя и условие по наличию файловых вложений. Все заданные условия должны совпасть. Если одному письму подходят несколько правил, применяется первое в списке.
2. **Папки Outlook.** Источник по умолчанию — «Входящие». Укажите три папки для очереди, успешной обработки и ошибок. Вставьте путь из Outlook, например `Входящие/Необработанные` или `\\Имя ящика\Входящие\Необработанные`, либо выберите папку в дереве. Exporter работает с основным ящиком Outlook. Если конечной папки нет, программа создаст её при запуске, когда родительская папка уже существует.
3. **Сохранение.** Выберите выгрузку вложений, письма `.msg` или обоих. Список расширений ограничивает отдельно выгружаемые файлы. Пустой список разрешает все файловые вложения. Вставьте путь из Проводника, например `C:\Отчёты\Выгрузка`, или выберите каталог. Относительный путь считается от папки с `config.toml`. Для выгрузки нужен локальный каталог на файловой системе с поддержкой жёстких ссылок, например NTFS.

По умолчанию отбор во входящих начинается с первого рабочего запуска правила. Эта граница сохраняется в журнале после перезапуска. Включите обработку уже полученных писем, если нужно разобрать накопившиеся входящие. Письма, которые уже находятся в «Необработанных», обрабатываются в обоих режимах.

Проверка отбора показывает, сколько писем в исходной папке соответствуют фильтру, включая уже полученные. Она помогает уточнить тему и отправителя до запуска и не меняет Outlook. Период проверки и путь к журналу задаются в общих настройках.

Старые правила с `source` и `move_to` сохраняют прежний режим. Чтобы перейти на новый процесс, откройте старое правило в мастере, выберите переход и проверьте фильтр, папки и каталог выгрузки. Для старого правила Outlook, которое уже переносит письма в «Необработанные», используйте ту же папку очереди. Чтобы весь отбор делал Exporter, отключите это правило в Outlook. Перед запуском отключите старый макрос VBA для тех же папок.

## Выгрузка

После сохранения настроек запустите Exporter из PowerShell. Пробный проход показывает план без записи. `--once` выполняет один рабочий проход. Для непрерывной обработки оставьте последний процесс запущенным. Новое письмо запускает проверку по событию Outlook, если Outlook доставляет это событие. Резервная проверка выполняется по заданному интервалу. После изменения настроек перезапустите Exporter. [Событие Items.ItemAdd](https://learn.microsoft.com/en-us/office/vba/api/outlook.items.itemadd)

```powershell
python outlook_exporter.py --config config.toml --dry-run
python outlook_exporter.py --config config.toml --once
python outlook_exporter.py --config config.toml
```

В новом процессе подходящее письмо сначала попадает в «Необработанные». Exporter сохраняет выбранные файлы и затем переносит письмо в «Обработанные». Если подходящих вложений нет, обработка завершается успешно, а журнал показывает, почему файлов нет. Сбой сохранения, дубликат или ошибка переноса ведут в папку «Ошибка». Если Outlook отклоняет и этот перенос, программа пишет причину в журнал и сохраняет письмо в текущей папке. При нехватке места письмо ждёт в очереди до следующей проверки. На диске остаётся резерв 256 МиБ.

SQLite-журнал по умолчанию хранится рядом с `config.toml` в `.outlook-exporter.sqlite3`. Он связывает письмо с сохранёнными файлами, чтобы повторный проход после сбоя не создавал копии. Дубликаты определяются по почтовому `Message-ID` в пределах правила, если Outlook может его прочитать. При отсутствии `Message-ID` журнал различает письма по Outlook EntryID. Файлы с совпавшими именами получают числовой суффикс.

В зависимости от настроек безопасности Outlook может запросить разрешение на чтение данных письма. [Предупреждения безопасности Outlook](https://learn.microsoft.com/en-us/office/vba/outlook/how-to/security/outlook-object-model-security-warnings)
