# Outlook Exporter

Программа выгружает вложения и письма из основного ящика текущего профиля классического Outlook для Windows. Запускайте её в обычном сеансе Windows, где Outlook уже настроен. [Сравнение версий Outlook](https://support.microsoft.com/en-us/outlook/getstarted/feature-comparison-between-new-outlook-and-classic-outlook#bkmk_extensibility)

## Подготовка компьютера

Скопируйте папку проекта на рабочий компьютер. Используйте CPython 3.10 или 3.11 и рабочее окружение с уже установленным `pywin32==305`. Для Python 3.10 также нужен `tomli==2.0.1`. Версии взяты из списка `requirements-workstation — копия.txt` проекта `Bond_recons`. [Сборки pywin32 305](https://pypi.org/project/pywin32/305/#files)

При необходимости создайте отдельное окружение в PowerShell. Если зависимости уже есть в рабочем Python, пропустите этот шаг.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

В командах ниже `python` обозначает Python из рабочего окружения. Если создали `.venv`, используйте `.\.venv\Scripts\python.exe`.

## Мастер настройки

Откройте классический Outlook. В PowerShell из папки проекта запустите мастер.

```powershell
python outlook_setup.py --config config.toml
```

Мастер открывается в браузере по адресу `http://127.0.0.1:8765`, доступному только с этого компьютера. В нём задаются папки текущего Outlook, каталоги выгрузки и условия обработки. Мастер сохраняет правила в `config.toml`.

Добавьте по одному правилу на папку-источник.

1. **Откуда брать письма.** Выберите папку в дереве Outlook или введите путь вручную. Чтобы создать папку, откройте её родительскую папку и нажмите **Создать в Outlook**. Новая папка появится сразу после нажатия. Так можно создать папки источника и назначения.
2. **Куда сохранять файлы.** Выберите каталог в системном окне Windows или введите путь. Относительный путь считается от папки с `config.toml`. Если указать новый каталог, Exporter создаст его при первой записи. Используйте обычный локальный каталог на NTFS или другой файловой системе с поддержкой жёстких ссылок. OneDrive может автоматически синхронизировать выбранную папку, включая рабочий стол и документы при включённом резервном копировании. [Настройки резервного копирования OneDrive](https://support.microsoft.com/en-us/onedrive/back-up-your-folders-with-onedrive)
3. **Что сохранять.** Можно выгружать отдельные вложения, целое письмо в формате `.msg` или оба варианта. Список расширений действует на отдельно сохраняемые файлы. Пустой список разрешает все файловые вложения. Файл `.msg` включает тело письма и его исходные вложения.
4. **Какие письма обрабатывать.** В разделе **Условия отбора писем** можно указать фрагмент темы и выбрать только непрочитанные письма. Условия применяются вместе, если заданы оба.
5. **Куда переносить письмо.** При заданной папке назначения программа переместит письмо после успешной выгрузки. Пустое поле оставляет письмо в исходной папке. Для назначения выбирайте обычную почтовую папку. Системные папки «Удалённые», «Исходящие», «Нежелательная почта» и их подпапки для переноса недоступны.
6. **Отметить прочитанным после выгрузки.** Включите этот параметр, если хотите, чтобы Exporter отмечал успешно выгруженное письмо прочитанным после проверки файлов. По умолчанию галочка снята. Письмо с запросом уведомления о прочтении останется непрочитанным.

В **Общих настройках** задаются интервал проверки, создание и настройка цветов категорий Outlook и путь к журналу. Нажмите **Проверить**, при необходимости включив проверку папок Outlook, затем **Сохранить настройки**. Закройте мастер через `Ctrl+C` в PowerShell.

Образец `config.example.toml` проверяет «Входящие → Необработанные» каждые 30 секунд, сохраняет вложения Excel из непрочитанных писем в `./exported` и после выгрузки переносит письма в «Входящие → Обработанные». При ручном редактировании каждый блок `[[routes]]` задаёт отдельное правило. Первый элемент пути `Inbox` или `Входящие` обозначает системную папку «Входящие».

Чтобы ежедневные отчёты попадали в «Необработанные» сами, направьте их туда правилом Outlook. Если хотите обойтись без правила Outlook, укажите «Входящие» как источник и задайте фрагмент темы отчёта в мастере.

При переносе `config.toml` на другой компьютер проверьте в мастере папки текущего Outlook и локальные пути.

## Выгрузка

После сохранения настроек запустите Exporter отдельно. Начните с пробного прохода. Он показывает план в терминале и обращается к Outlook только для чтения. Затем можно выполнить один проход с записью через `--once` или запустить постоянную проверку.

```powershell
python outlook_exporter.py --config config.toml --dry-run
python outlook_exporter.py --config config.toml --once
python outlook_exporter.py --config config.toml
```

Постоянная проверка работает до `Ctrl+C`. При первом проходе программа проверяет и накопившиеся письма. С настройкой **Только непрочитанные** новые выгрузки выполняются для писем, которые Outlook считает непрочитанными на момент проверки. Если прервался только перенос уже выгруженного письма, программа продолжит его после запуска, даже если письмо прочитано. После изменения настроек перезапустите Exporter, чтобы применить их.

Exporter сохраняет файлы, проверяет их на диске, ставит письму статус «Выгружено» и затем переносит его. При сбое до завершения переноса письмо остаётся в очереди. Exporter использует файлы, записанные в журнале, и восстанавливает отсутствующие при повторной выгрузке. Если подходящих файлов нет, письмо остаётся в исходной папке со статусом «Нет файлов» или «Нет нужных файлов». При ошибке выгрузки появляется статус «Ошибка выгрузки».

При переносе Exporter сравнивает точный `Message-ID` письма из почтовых заголовков с письмами в папке назначения. Если там уже есть письмо с таким идентификатором, статусом «Выгружено» и отметкой завершения, копия остаётся в исходной папке со статусом «Дубликат». При включённом управлении цветами категория серая. Письма с одинаковыми темами и именами вложений обрабатываются отдельно, если их `Message-ID` различаются. Когда почтовый идентификатор отсутствует, журнал опирается на внутренний Outlook EntryID отдельного письма. Другие копии такого письма могут иметь другой EntryID.

Имя выгруженного файла начинается с даты и времени получения письма. При совпадении имён программа добавляет числовой суффикс. По умолчанию журнал `.outlook-exporter.sqlite3` хранится рядом с `config.toml`, а файл блокировки `.outlook-exporter.sqlite3.lock` создаётся рядом с журналом. Каждое правило должен обслуживать один экземпляр Exporter. Перед запуском отключите старый макрос VBA для тех же папок.

В зависимости от настроек безопасности Outlook может запросить разрешение при чтении `Message-ID`. Действующие настройки защиты Outlook применяются и к Exporter. [Предупреждения безопасности Outlook](https://learn.microsoft.com/en-us/office/vba/outlook/how-to/security/outlook-object-model-security-warnings)

Outlook Exporter сохраняет файлы только в локальные каталоги, не открывает вложения и не отправляет письма. При нехватке места выгрузка приостанавливается до следующего прохода. На диске с каталогом выгрузки программа оставляет резерв 256 МиБ.
